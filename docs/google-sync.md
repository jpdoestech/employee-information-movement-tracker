# Google Sheets operating guide

Use a personal Google account with a Google Cloud OAuth **Web application** client, Sheets/Drive APIs enabled, exact callback URL and external consent/test users as appropriate. This implementation requests offline `drive.file` access and creates its own root folder in that user's My Drive. Existing arbitrary folders are not assumed accessible; a future folder chooser must use Google's Picker/access flow before supporting them. Do not assume a service account can own files in consumer My Drive.

Connect from the Superadmin Sync screen. A ten-minute, hashed, single-use state is bound to the initiating active Superadmin. Refresh tokens are AES-GCM encrypted in a private schema; the 32-byte key and OAuth client secret exist only in backend secrets. Access tokens are short-lived and never returned to the browser. Consent in Google's external Testing status commonly expires offline refresh authorization after seven days; complete the required publishing/verification process for continued production operation. Reconnect after revocation or expiry.

Each branch and Head Office receives a stable workbook mapping. Approve its client rows, directly assigned primary roster, normal column keys, fixed system metadata and sharing emails before synchronization. Employee ID must be allowed. Sensitive/restricted fields are rejected. The four managed tabs are `Employees_Current`, `Assignments_Current`, `Movement_History`, and hidden `Sync_Metadata`. Fixed metadata includes immutable IDs, revisions, effective dates and synchronization timestamps; approval covers this explicitly. Client IDs in assignment rows are omitted unless the client column is approved. No additional-assignment roster or private movement reason is exported.

Sharing is independent of application RBAC. Only the owner and explicitly approved individual user emails are accepted; anyone, domain and group grants suspend synchronization. Folder-inherited permissions also require review. No automatic public sharing is created. An app user's field access is never sufficient to authorize a Sheets column. Changing a policy does not revoke access to a previously downloaded spreadsheet; revoke inappropriate Drive access and remove historical copies through the organization's data handling procedure.

Supabase commits first. Audit and branch-routed outbox events commit atomically with writes. A scheduler calls the authenticated worker; it claims exclusive leases, reads the latest canonical projection, checks current approval and actual sharing, writes literal strings with atomic batch replacement, and records the revision. Stable workbook properties and employee/field keys prevent duplicate creation and label-based columns. Transfers route both source and destination branches; reconciliation removes departed employees from the old **current-roster** workbook. Supabase retains authoritative history. Future-dated changes are reconciled when the Manila business date changes. Sheet edits are overwritten on reconciliation and never flow back.

Retry with exponential delay and jitter; leases recover interrupted runs, and retries replace rather than append rows. Eight failed attempts enter failed state; review the underlying problem and use Reconcile after repair. Monitor Pending, Failed and Suspended workbooks and outbox backlog. Revoked consent, 429/network timeouts, unavailable storage and ownership/sharing changes must be exercised in staging. A worker run is bounded to about 110 seconds and 200 outbox events; each workbook is bounded to 1,000 roster rows. Route-aware revision skipping avoids rewriting already current books. Sustained larger workloads require measured partitioning/chunking before rollout.

Unsafe sharing and newly restricted exported fields stop projection rather than silently broaden access. Existing Sheets cells can remain stale while suspended: promptly revoke Drive sharing and purge affected managed cells under a trusted operational procedure before reapproval. Renames, inactive ordinary fields and row changes are removed deterministically during the next successful full replacement. Never put PII, secrets or token payloads in diagnostic logs.

Google's quota currently documents 300 read/write requests per minute per project and 60 per user; measure actual volume, batch writes and honor retry delays. The worker is one sequential account-bound process, not an unlimited fan-out service.
